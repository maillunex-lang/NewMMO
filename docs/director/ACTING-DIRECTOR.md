## Твой рабочий цикл (как у директора)
1. Владелец пишет «T-NNN готово» (+ отчёт исполнителя). Ты делаешь `git fetch origin 'refs/heads/agent/*:refs/remotes/origin/agent/*'`, смотришь `git log`/`git diff --stat` ветки `agent/<lane>/T-NNN` против `git merge-base origin/main <ветка>`.
2. Проверки: `python3 tools/director/lane_check.py --range <base>..<ветка>` (0 нарушений); gates из `DIRECTOR.md` §3; diff по списку приёмки задачи; нет секретов; новых зависимостей сверх одобренных нет.
3. Если всё хорошо — слей **не fast-forward** в `main` (`git merge --no-ff`, коммит с трейлерами `Lane: director` / `Task: T-NNN`), `git push origin HEAD:main`, **дождись зелёного CI на `main`** (все 6 джобов: server, server-db, client-godot, content-lint, client-scripts, lane-check). Красный — читай логи и чини или откатывай слиянием-ревертом, не `force-push`.
4. Если плохо — напиши исполнителю rework (файл `docs/director/prompts/T-NNN-rework-N.md`) с конкретными пунктами; не правь за него его lane.
5. Обнови `TASKS.md` (статус + SHA + заметки) и `ROADMAP_EXECUTION.md` (чекбокс этапа + SHA + тесты), закоммить в `main`. Ты — единственный, кто их пишет.

## Research-first (коротко, до кода)
Проверь практику: OWASP Password Storage Cheat Sheet (PBKDF2-HMAC-SHA256, число итераций), документация Go `crypto/pbkdf2` (стандартная библиотека, Go ≥ 1.24), `crypto/rand`, `crypto/subtle`, паттерны одноразовых тикетов/rate limit, GitHub и **каталог Hysen Labs https://hysenlabs.com/projects**. ≥3 варианта в `docs/research/T-018-auth-notes.md` (что взял, что отверг; **новые зависимости запрещены** — только stdlib и уже разрешённый pgx).

## Что сделать
1. **Миграции** `server/migrations/00006…` (goose, `Up/Down`): таблицы из контракта (`accounts, auth_tokens, login_attempts, characters, ws_tickets`) с CHECK/индексами/триггерами как в `db-gameplay.md`; **гранты роли `newmmo_app`** (DML на эти таблицы, без DDL; логин-попытки и токены — по необходимости только нужные операции). Корректный `Down`. Лимит «≤ 3 персонажа на аккаунт» — под блокировкой строки аккаунта в той же транзакции.
2. **Пакет** `server/internal/auth` (+ при необходимости `server/internal/api`): хеширование PBKDF2 по контракту (формат строки, 600 000 итераций, повторное хеширование при логине, если итераций меньше текущего), сравнение в постоянное время, выравнивание времени для неизвестного логина, токены и билеты (хранение только SHA-256, TTL, одноразовость билета через один атомарный `UPDATE … RETURNING`), лимиты попыток (5/15 мин на пару логин+IP, 20 на IP; создание аккаунтов 5/час на IP), никаких секретов в логах/ошибках.
3. **REST-ручки** `/v1/accounts`, `/v1/auth/login`, `/v1/auth/logout`, `/v1/characters` (GET/POST), `/v1/session/ticket` — ровно по контракту (коды ошибок, формат тела ошибки, лимит тела 4 КиБ, строгая валидация, неизвестные поля → 400, 64-битные id строками). Подключи их в существующий `httpservice` (middleware логирования/request-id остаётся; `/healthz` без изменений; `/readyz` теперь учитывает доступность БД).
4. **Конфигурация** из окружения: `NEWMMO_DATABASE_URL` (роль `newmmo_app`), `NEWMMO_PUBLIC_WS_URL`, лимиты (с дефолтами из контракта). Сервер **не** запускает миграции; при недоступной БД — понятная ошибка запуска.
5. **Тесты** (юнит без БД + интеграционные с БД по схеме CI `server-db`, три роли, `NEWMMO_REQUIRE_ROLE_URLS=1`): формат и перехеширование пароля; успешные и неуспешные сценарии каждой ручки; одинаковый ответ для неверного логина/пароля; rate limit; токен/билет в БД только в виде хеша (тест читает таблицу); билет: второе использование отклоняется, просроченный, чужой персонаж; **конкурентное** использование одного билета (ровно один успех); лимит 3 персонажей при конкурентном создании; отсутствие секретов в логах (тест); права роли `newmmo_app` (нельзя DDL). `go vet`, `go test -race`, `go mod verify`; в CI добавлен `govulncheck` (запусти локально, если можешь: `GOTOOLCHAIN=auto go install golang.org/x/vuln/cmd/govulncheck@v1.10.0`).

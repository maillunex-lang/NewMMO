Ты — исполнитель **Cursor (lane `client`)** проекта Lunex MMORPG. Писать в репозиторий можно: `client/**` (кроме `client/data/**`), **`tools/android/**`** (разрешено через `Extra-Write: tools/android/**`), заметку `docs/research/T-012-*.md`.

## Research-first (до установки чего-либо)
Требования **Godot 4.3** (не 4.7.2!) берёшь из официальной документации 4.3 «Exporting for Android»: версии JDK, Android SDK (platform, build-tools, platform-tools), нужны ли NDK/CMake/Gradle для **предсобранного** (non-Gradle) debug APK, откуда брать export templates 4.3-stable и контрольные суммы. Проверь также GitHub (godot-ci и др.) и **каталог Hysen Labs https://hysenlabs.com/projects** — как другие воспроизводимо готовят Android-экспорт Godot. ≥3 варианта в `docs/research/T-012-android-baseline-43.md` (напр.: ручная установка SDK + sdkmanager; godot-ci Docker; Android Studio) и обоснованный выбор (предпочтительно минимальный набор без Android Studio).

## Что разрешено устанавливать (ничего сверх списка)
JDK 17 (Temurin/OpenJDK официальная сборка), Android SDK command-line tools + `platform-tools` + нужные `platforms;android-NN` и `build-tools;NN` (точные версии — по документации 4.3), Godot 4.3-stable export templates. Всё — **в каталог пользователя** (например `~/android-sdk`, `~/jdk`), не системно, **без `curl | bash`**: сначала скачать файл, **сверить SHA-256 с официальной страницей**, потом распаковать. Версии и суммы записать в research-файл.
Неразрешено: Android Studio, эмуляторы, Gradle/NDK (если документация 4.3 для prebuilt APK их не требует), любые сторонние плагины/ассеты.

## Что сделать
1. Установить инструментарий по плану; настроить Godot **через настройки редактора** (`export/android/java_sdk_path`, `android_sdk_path`, debug keystore) — они лежат **вне репозитория**.
2. **Debug keystore** создать локально (`keytool`), хранить **вне репозитория**; пароль — в окружении/файле вне репо. Ничего подобного в git: `*.keystore`, `*.jks`, `.env` игнорируются, и всё равно не коммить; `export_presets.cfg` не должен содержать секретов (если сейчас содержит пути/пароли — убери, оставив настройку на уровне редактора).
3. Собрать `LunexMMORPG-debug.apk` командой `godot --headless --path client --export-debug Android <путь вне git или build/>` (папка `client/build/` игнорируется git). Проверить: непустой APK, `apksigner verify`, package `com.lunex.newmmo`, ABI, **minSdk/targetSdk и версию из манифеста** (`aapt2 dump badging` или аналог), размер, наличие `res://data/quests|dialogues/*.json` внутри.
4. Скрипты в `tools/android/`: `build_debug_apk.sh` (воспроизводимая сборка: пути из переменных окружения, проверки, вывод итоговой сводки) и `measure_device.sh` (adb-протокол замеров, см. п.5). Скрипты не должны содержать секретов и не должны трогать ничего вне проекта/каталога вывода.
5. **Замеры на телефоне 6 ГБ RAM:** если у тебя есть доступ к устройству по `adb` — установи APK и сними **по три** прогона: время холодного старта, FPS и p95 времени кадра за 5 минут движения (`dumpsys gfxinfo`/встроенный монитор Godot — выбери и опиши), peak PSS (`dumpsys meminfo`), размер APK, падения/ANR, температура/троттлинг (если доступно). Каноническая цель 30 FPS на low. Если устройства нет — **честно** напиши «устройство недоступно», выдай APK и пошаговый протокол, который владелец выполнит сам (`measure_device.sh`), и **не выдумывай цифры**.
6. Зафиксируй **базу 4.3**: точный `godot --version`, SHA коммита, модель/ОС устройства, графические настройки — чтобы позже сравнивать с 4.7.2 (гейт `godot-4-7-2-upgrade.md` §6).

## Не делать
Не обновлять Godot, не менять `config/features`; не коммитить APK/keystore/SDK/шаблоны/пароли; не трогать `client/data/**`, `server/**`, CI, канон, контракты, `tools/**` кроме `tools/android/**`; не менять игровую логику; не подключаться к чужим устройствам/сервисам.

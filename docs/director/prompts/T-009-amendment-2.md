# T-009 — поправка №2 (ответ на твой блокер R-04 и порядок завершения)

Продолжай **в той же ветке `agent/server/T-009`** (черновик у тебя локально). Контракты снова обновлены: `git fetch origin && git rebase origin/main`, затем перечитай `docs/contracts/db-content.md` (раздел **«`ingest_digest`»**, §2–§3, §6) — это ответ на твой вопрос.

## Решения директора
1. **R-04 решён:** `ingest_digest` считает **сам PostgreSQL из сохранённых строк после вставки** (формула в контракте, `payload::text` — детерминированная текстовая форма jsonb; поля, присланные клиентом, в хеше не участвуют). Колонка `content_entities.line_sha256` **удалена из контракта** — убери её из миграций и кода. Привязка к байтам бандла остаётся на входе (проверка `entities_sha256` до вставки). Пересчёт — на `Stage` (повтор) и обязательно на `Publish`. Твою пробу «замена payload при тех же счётчиках» **превращай в тест**: должна давать отказ на Publish.
2. **Артефакт `manifest.json` в ссылках** — исправлено мной в `tools/content/check_docs_links.py` (после rebase `check_docs_links.py` даёт 0).
3. **Проверка `schema_version` на Rollback** — реализуй (контракт §3): целевой билд с неподдерживаемой версией ⇒ `SCHEMA_UNSUPPORTED`.
4. **Compose / права init-каталога:** не монтируй каталог с init-скриптами bind-ом. Используй `configs:` Compose (файл/inline) или `docker-entrypoint-initdb.d` с файлами `0644` в каталоге `0755`; проверь, что стек поднимается с нуля (`docker compose down -v && up`). Digest образа, который ты закрепил (`sha256:b60e9004…`), — оставляй.
5. **Создание ролей** (`newmmo_migrator`, `newmmo_content_publisher`, `newmmo_app`) — в init-скрипте Compose/CI-сервиса; миграции выдают гранты. Опиши в `deploy/newmmo/README.md`. Директор поправит CI `server-db` под твой init после мержа (если нужно — напиши, что именно требуется, в отчёте).

## Порядок завершения (по приоритету; каждый этап — отдельный коммит + push)
1. Миграции rev 1.1 (seed указателя, поля, CHECK-и, роли/гранты, триггеры: переходы, неизменяемые колонки, TRUNCATE, защита указателя, append-only audit) + `up → reset → up` на чистой БД.
2. Верификатор бандла rev 1.1 (BUILD_ID по сырым байтам, строгий разбор, лимиты, потоковое чтение) + юнит-тесты без БД.
3. Хранилище (Stage/Publish/Rollback с `expected_current`, порядок блокировок, ретраи 40P01/40001, SQL-`ingest_digest`, коды ошибок, best-effort audit).
4. `contentctl` (verify/stage/publish/rollback/status).
5. Интеграционные тесты по приёмке §6 (в т.ч. две одновременные первые публикации, прямой DML от `newmmo_app`, подмена payload).

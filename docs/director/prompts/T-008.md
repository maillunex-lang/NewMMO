## Проблемы (подтверждены директором)
1. `tools/smoke_stage1.sh`: импорт запускается с `|| true` (ошибка импорта игнорируется), а скрипты `stage1_smoke.gd` и `mq01_smoke.gd` в нём **не запускаются** — только boot и `go test`.
2. `mq01_smoke.gd` печатает `MQ01_SMOKE_OK` **до** проверки `xp`; успех определяется только кодом выхода.
3. `export_presets.cfg`: `include_filter=""` — файлы `client/data/**/*.json` могут не попасть в APK (квесты/диалоги не загрузятся на телефоне).

## Что сделать
1. `tools/smoke_stage1.sh`: строгий режим — код выхода импорта проверяется (если «шумный» ненулевой код на чистом клоне бывает штатным — зафиксируй это экспериментом на своей машине и обработай явно с логом, а не молчаливым `|| true`); добавить запуск `stage1_smoke.gd` и `mq01_smoke.gd` (`--headless --script ...`), требуя код 0 **и** маркер успеха в выводе; итоговый `Smoke OK` только если всё прошло. Сохранить обратную совместимость: переменная `GODOT`, серверная часть `go test`.
2. `mq01_smoke.gd`: маркер успеха печатать только после всех проверок (включая xp).
3. `export_presets.cfg`: добавить `include_filter="data/*.json,data/**/*.json"` (проверь синтаксис по документации экспортных фильтров). Проверить экспортом (если есть шаблоны) или объяснить, как проверить вручную: что JSON лежат в APK/PCK.
4. Отчёт: «до/после» вывод смоука; что проверено, что нет.

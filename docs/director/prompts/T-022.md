## Что сделать
1. **REST-клиент** `client/scripts/net/auth_client.gd` (+ абстракция HTTP-транспорта и `FakeHttp` для тестов): методы по контракту (`register`, `login`, `logout`, `list_characters`, `create_character`, `request_ticket`), разбор ошибок `{"error":{"code","message_key"}}`, коды HTTP, таймауты, повтор запрещён для небезопасных операций. Адрес сервера — из настройки/переменной (`NEWMMO_API_URL`, по умолчанию `http://127.0.0.1:18086`), **без хардкода хостов в сцене**.
2. **Экраны** (редактируемые `.tscn`, Theme, safe-area, ≥48 dp, landscape; **раскладка в сцене, не в коде**): вход / регистрация; список персонажей; создание персонажа (имя + выбор класса из 5 канонических `CLS-01…05` с названиями из канона — названия приходят из данных, не из GDScript); состояние ошибок и ожидания. Все надписи через `tr()` и `client/translations/ui.csv`.
3. **Безопасность на клиенте:** пароль только в `LineEdit(secret)`, **никогда не пишется на диск и в лог**; access token — **только в памяти**; на диске (`user://`) допускается лишь последний введённый логин (по желанию игрока). После `request_ticket` экран эмитит сигнал `session_ticket_ready(ticket, ws_url, character)` — **подключения к игре нет** (оно в следующей задаче).
4. **Тесты** `client/scripts/dev/auth_smoke.gd` (headless, маркер `AUTH_SMOKE_OK` только после всех проверок): успешные и ошибочные ответы каждого метода (`FakeHttp`), разбор кодов `INVALID_CREDENTIALS`/`LOGIN_TAKEN`/`RATE_LIMITED`/`LIMIT_REACHED`, сигнал `session_ticket_ready`, отсутствие пароля/токена в логах и на «диске» (проверка файлов `user://` в тесте). Подключить в `tools/smoke_stage1.sh` тем же строгим шаблоном (код 0 + маркер); искусственный сбой даёт ненулевой код.
5. Основная игровая сцена **не меняется** (игра продолжает стартовать как раньше); экран входа запускается отдельной dev-сценой/флагом.

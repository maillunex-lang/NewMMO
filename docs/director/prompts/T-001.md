## Цель
Выбрать инструмент(ы) для: (a) версионируемых SQL-миграций PostgreSQL с up/down, (b) доступа к БД из Go-сервера (драйвер/пул, при желании генерация типобезопасного кода), (c) загрузки контента (`content_builds`, `content_entities`, атомарная публикация, rollback) — см. `14` §16.

## Что сделать
1. Сравни **не менее 3** (лучше 5–6) кандидатов, например: goose, golang-migrate, Atlas, dbmate, tern; pgx/pgxpool, database/sql+lib/pq; sqlc, Bun/ent/GORM (как «не брать»). Добавь кандидатов, найденных через Hysen Labs/GitHub.
2. Критерии: лицензия (SPDX), активность (последний релиз/коммит), поддержка Go 1.22, PostgreSQL-специфика (транзакционный DDL, advisory locks, jsonb), rollback/down, запуск из бинаря (embed) и из CI, работа в изолированном Docker Compose, размер/зависимости, риски lock-in, безопасность (supply chain).
3. Отдельно: нужен ли вообще внешний инструмент, или достаточно ~150 строк stdlib + `database/sql`? Честно оцени.
4. Рекомендация + запасной вариант + что именно потребуется установить (точные версии/модули) — **но ничего не устанавливай**.
5. Приложи минимальный пример структуры каталога миграций (имена файлов), без SQL-реализации схемы.

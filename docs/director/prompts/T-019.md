## Что сделать
1. Эндпоинт WebSocket на существующем `httpservice` (middleware остаётся; апгрейд должен работать через logging wrapper — HTTP 101, `Hijack`). Subprotocol `newmmo.v1`; только текстовые JSON-кадры; строгий разбор (дубликаты ключей, неизвестные поля, размер, глубина — по контракту §2–§3).
2. Жизненный цикл по §4: pre-auth таймер 5 с, до auth принимается только `session.auth`; атомарное одноразовое погашение билета (используй код T-018); `session.ready` → `content.version` → `state.snapshot` (скелет: `character`, `scopes.quests: {active:[], completed:[], available:[]}`, `revision` — квесты придут в T-020); `character_id` берётся из билета, не из сообщений.
3. Heartbeat: Ping каждые 25 с, закрытие без Pong за 15 с. Newest session wins: старая сессия закрывается кодом `4005`. Реестр сессий.
4. Лимиты §8: handshake 10/мин на IP, pre-auth ≤3 на IP, token bucket 20/с burst 40, одна ограниченная очередь отправки (256) и один writer-цикл, write timeout 10 с, медленный потребитель закрывается `1013` и не блокирует других, нарушения → `RATE_LIMITED`/`4003`. Значения — из конфигурации с дефолтами контракта.
5. Graceful shutdown (SIGTERM): перестать принимать, закрыть все сессии `1001`, дренаж ≤ 10 с.
6. Неизвестные/ещё не реализованные команды → `command.error` с кодом из контракта (не паника и не молчание). Никаких секретов, билетов, токенов в логах (id, размеры, коды).
7. **Тесты** (юнит + интеграционные с БД по схеме CI `server-db`): апгрейд через wrapper; неверный subprotocol/бинарный кадр/слишком большой/кривой JSON/дубликат ключа; pre-auth таймаут; билет одноразовый (в т.ч. **конкурентное** использование — один успех), просроченный, чужой персонаж; heartbeat (Pong-таймаут); медленный потребитель → `1013` без блокировки остальных; newest-wins `4005`; shutdown `1001`; rate limits; отсутствие секретов в логах. `go vet`, `go test -race`, `go mod verify`, `govulncheck` чисто. Пункты §10 контракта → таблица «пункт → тест» в отчёте.

## Цель
Изолированная клиентская библиотека протокола v1 в `client/scripts/net/`, **не подключённая к игровому процессу** (квесты остаются локальным stub до EX-P04). Она должна быть полностью проверяема без сервера через подменяемый транспорт.

## Что сделать
1. **Транспорт-абстракция** (интерфейс: `connect/poll/send_text/close/state/…`) + реализация на `WebSocketPeer` + **FakeTransport** для тестов. Только текстовые JSON-сообщения, подпротокол `newmmo.v1`, без сжатия; `poll()` каждый кадр.
2. **Конверт и валидация** по контракту §2–§3: сборка C→S (`protocol_version`, `type`, `request_id` UUIDv4 для мутаций, `payload`); разбор и **строгая проверка S→C** (обязательные поля, `revision` как целое < 2^53, неизвестные `type` — игнор + лог, мусорный JSON — не падать); 64-битные id — строки.
3. **Сессия** (state machine): CONNECTING → AUTHING (`session.auth` с билетом из подменяемого провайдера, таймаут ожидания) → READY (`session.ready`, `content.version`, `state.snapshot`) → RECONNECTING; backoff 0.5, 1, 2, 4, 8, 15 с + jitter; обработка close-кодов 4001–4005 по контракту §4 (напр. 4005 — не переподключаться автоматически, 4002/4004 — сообщить «нужно обновление»).
4. **Ревизии**: `last_revision`; дельты применяются строго по порядку; разрыв последовательности или реконнект ⇒ `state.snapshot.request` и **отбрасывание дельт до снимка**; после снимка применять только `revision > snapshot.revision`.
5. **Идемпотентность**: очередь неподтверждённых мутаций; после реконнекта повтор **с тем же `request_id`**; ответ с тем же `request_id` закрывает запись; `command.error` коррелируется по `request_id`; `RATE_LIMITED` ⇒ повтор не раньше `retry_after_ms`.
6. **API для UI** — сигналы/методы (подключиться, отправить `quest.accept.request`/`quest.turnin.request`/`dialogue.*`, получать `quest.progress.delta`/`quest.reward.granted`/`dialogue.node.state`/`inventory.delta`/`command.error`/`session state`). Не менять `quest_manager.gd` и сцены, не подключать к игре.
7. **Тесты** `client/scripts/dev/net_smoke.gd` (headless, `MARKER NET_SMOKE_OK` только после всех проверок, иначе ненулевой код): валидные/невалидные S→C, порядок ревизий и разрыв, реконнект с backoff (детерминированный генератор для jitter), повтор мутации с тем же `request_id`, дубликат ответа, `command.error`, close-коды, неизвестный `type`, битый JSON, подпротокол/без сжатия. Подключить в `tools/smoke_stage1.sh` тем же строгим шаблоном (код 0 + маркер).

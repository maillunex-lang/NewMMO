## Цель
Рабочий путь «экспортный бандл контента → PostgreSQL → атомарная публикация/откат» с миграциями и тестами.

## Что сделать
1. **Миграции** `server/migrations/NNNNN_*.sql` (goose SQL, `-- +goose Up/Down`) строго по `db-content.md` §2/§4: `content_builds`, `content_entities` (+индексы), `content_active`, `content_audit`, триггеры неизменяемости. Имена файлов — как в контракте.
2. **Go-пакет** `server/internal/content/`: чтение и **полная верификация** бандла (`content-export.md` §4: хеши, счётчики, 7 ключей, уникальность id, schema_version) — на stdlib, без БД; хранилище на `pgx/v5`+`pgxpool`: `Stage`, `Publish(build_id, expectedPrevious)`, `Rollback(to)`, `ActiveBuildID`, чтение сущностей по `build_id`, запись `content_audit`. Транзакции и блокировки — как в §3 контракта. Конфиг из env (`NEWMMO_DATABASE_URL` и др., §5), секреты не логировать.
3. **CLI** `server/cmd/contentctl` (stdlib `flag`): `verify <dir>`, `stage <dir>`, `publish <build_id> [--expected-previous <id>]`, `rollback <build_id>`, `status`. Сервер **не** мигрирует автоматически и в этой задаче не подключается к БД при старте (`/readyz` не меняется).
4. **Изолированный Compose** `deploy/newmmo/compose.yml` + `README.md` + `.env.example`: свой project name (`newmmo-dev`), своя сеть/volume, Postgres 17, порт только на `127.0.0.1` (нестандартный, напр. 15432), пароль из `.env` (в git только `.env.example` с заведомо фиктивным значением). Не трогать и не подключаться к чужим стекам, Caddy, VPS. Тег образа без digest — допустимо; digest зафиксируй в отчёте, если сможешь `docker pull`.
5. **Тесты**: (a) юнит-тесты верификации бандла на маленьких фикстурах (корректный, подделанный manifest/entities/crossrefs, дубли id, неверные счётчики) — всегда запускаются; (b) интеграционные тесты с БД: пропускаются при пустом `NEWMMO_TEST_DATABASE_URL`; бандл берут из каталога `NEWMMO_CONTENT_EXPORT_DIR` (создаётся командой `python3 tools/content/export.py --out <dir>`) либо `t.Skip`. Покрыть пункты приёмки `db-content.md` §6 (up→down→up, stage реального бандла 4925 сущностей и счётчики по `kind`, подделка отклоняется, publish, повторный publish отклоняется, **конкурентный** publish — ровно один выигрывает, rollback, триггеры неизменяемости, идемпотентный re-stage, сбой посреди stage не оставляет частичный билд).
6. `server/go.mod`: допускаются **только** `github.com/jackc/pgx/v5 v5.13.0` и транзитивные зависимости по `go mod tidy`; `go.sum` закоммитить; `go mod verify` должен проходить. goose — **не** зависимость модуля (ставится отдельно: `GOTOOLCHAIN=auto go install github.com/pressly/goose/v3/cmd/goose@v3.30.0`).

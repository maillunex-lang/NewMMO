## Что проверить (минимум)
1. **Соответствие контракту:** по каждому пункту R-01…R-13 найди место в коде/тесте, которое его закрывает, и скажи, действительно ли тест может упасть при дефекте (не «зелёный всегда»).
2. **Гонки и блокировки:** порядок «указатель → билды по возрастанию `build_id`», `expected_current`, ретраи 40P01/40001, advisory lock на Stage; возможна ли взаимоблокировка между триггером `FOR SHARE` и publish; поведение при сбое посреди транзакции.
3. **Миграции:** корректность `Up/Down`, гранты на колонки, владельцы функций/триггеров, возможность обхода защиты ролью `newmmo_content_publisher` (прямые UPDATE `content_active`, DELETE staged, обход триггеров через `session_replication_role`/`ALTER TABLE ... DISABLE TRIGGER` — у каких ролей есть такое право).
4. **Верификатор бандла:** строгий разбор (UTF-8, BOM, дубли ключей на всех уровнях вложенности, NaN/Infinity, лимиты, сортировка), потоковое чтение (нет ли буферизации всего файла), обработка ошибок; попробуй придумать «грязный» вход, который пройдёт, но не должен.
5. **`ingest_digest`:** действительно ли вычисляется на стороне PostgreSQL по формуле контракта, нет ли расхождения формулы и кода, детерминизм `payload::text`.
6. **contentctl и конфигурация:** утечки секретов (DSN в логах/ошибках), коды выхода, безопасное обращение с аргументами.
7. **Compose и CI:** изоляция (проект/сеть/том/порт на loopback), пароли только из окружения, digest образа; CI-job `server-db`: корректна ли последовательность (роли → goose под migrator → тесты с тремя URL), нет ли способа, чтобы DB-тесты тихо пропускались.
8. **Зависимости:** `go.mod`/`go.sum` содержат только разрешённое (`pgx v5.13.0` + 5 косвенных); нет `replace`; лицензии (MIT/BSD) по тегам.

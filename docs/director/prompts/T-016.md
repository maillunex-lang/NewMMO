Посмотри, как профессионально проверяют и пишут диалоги квестов в RPG и как автоматизируют их проверку: GitHub, **каталог Hysen Labs https://hysenlabs.com/projects**, документация инструментов диалогов (Yarn Spinner, Ink, Dialogue Manager — только оценка идей линта/структуры), руководства по локализации игровых диалогов. ≥3 источника с выводами (что полезно взять как **правила**, не как зависимость). **Ничего не устанавливать.**

## Что сделать
1. **Измерения** (по `10_DIALOGUES.md`; если не можешь запустить код, считай по тексту и честно пиши метод и погрешность): число реплик, доля уникальных; топ повторяющихся реплик и «штампов» (дословные и почти-дубли) с числом вхождений; разбор по стадиям (START/OBJ/PROGRESS/TURNIN/DONE) и по спикерам (NPC/PLAYER/SYSTEM); START, где вклеен текст журнала; сколько квестов у каждого NPC; различимы ли голоса NPC между собой.
2. **Сверка с критериями плана** (§2, приёмка): таблица «критерий → факт → отклонение» для MQ и SQ.
3. **Голоса NPC:** для каждого именного NPC из диалогов — краткая «карточка голоса» по `04_CHARACTERS.md` (манера речи, лексика, запреты) и оценка, насколько текущие реплики её соблюдают (с 2–3 цитатами-доказательствами на NPC, с указанием ID реплик).
4. **Согласованность с состоянием квеста:** найди реплики, которые противоречат цели/стадии (например, звучат как после выполнения до выполнения), и места, где игрок «знает» то, чего ещё не должен (особенно по тайне Договора).
5. **Приоритизация переписывания:** предложи порядок батчей (REG-01 → …), для каждого батча — объём, риск, зависимости, оценка трудоёмкости; отметь, какие квесты требуют веток CHOICE по канону.
6. **Руководство по стилю** (`docs/research/T-016-dialogue-style-guide.md`): тон A (серьёзное фэнтези + институциональный сарказм; юмор не обесценивает жертв), правила длины реплик, шаблоны построения сцены по стадиям, как писать варианты ответа игрока (`ACCEPT`/`ASK`/`LATER`…), запрещённые штампы и слова, правила для SYSTEM-подсказок, правила локализации (короткие фразы, без склеек строк, без жёстко зашитых полов/склонений), как не ломать граф и серверные флаги, чек-лист самопроверки автора. Допускается не более 10 коротких **иллюстративных** строк, явно помеченных «пример, не канон».
7. **Спецификация автоматического линта диалогов** (для директора, в том же файле): конкретные правила (детектор штампов, порог дублей, длина, наличие всех стадий, спикер соответствует NPC квеста, запрет раскрытия тайны до гл. IV по маркерам, терминальные знаки и т.д.) с примерами срабатывания и порогами.

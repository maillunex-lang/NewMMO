# T-013 — Independent implementation review: EX-P03 (T-009)

**2026-11-21 · lane research · code review only.** Reviewed `main` at time of retrieval: contracts rev 1.1, four goose migrations, Go bundle/store/CLI/tests, isolated Compose, roles script, CI server-db and module pins. **No code, contract, CI, dependencies, DB or VPS changed.** Severity reflects risk of a real exploit or failed acceptance, not a claim that live PostgreSQL reproduction was performed.

## Research-first: practice checks

1. [PostgreSQL 17 explicit locking](https://www.postgresql.org/docs/17/explicit-locking.html), [isolation](https://www.postgresql.org/docs/17/transaction-iso.html): `FOR UPDATE` serializes pointer writers; `FOR SHARE` on build rows conflicts with status-changing updates. A consistent lock order and handling SQLSTATE `40P01`/`40001` matter. Source confirms the intended pattern, but **not** its execution in this code.
2. [PostgreSQL 17 trigger](https://www.postgresql.org/docs/17/sql-createtrigger.html), [privileges](https://www.postgresql.org/docs/17/sql-grant.html), [ALTER TABLE](https://www.postgresql.org/docs/17/sql-altertable.html): row triggers do not intercept TRUNCATE; table owner/superuser can disable ordinary triggers; column-level UPDATE grants do not restrict the *values* written to granted columns. Thus publisher direct-DML bypass below is substantive.
3. [PostgreSQL 17 COPY](https://www.postgresql.org/docs/17/sql-copy.html), [jsonb](https://www.postgresql.org/docs/17/datatype-json.html), [SQLSTATE appendix](https://www.postgresql.org/docs/17/errcodes-appendix.html): COPY is transactional, JSONB normalizes textual representation; `22P05` is an encoding/untranslatable-character error. Ingest digest must use stored JSONB, not raw bundle bytes.
4. [pgx v5 upstream](https://github.com/jackc/pgx), [pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool), [CopyFrom](https://pkg.go.dev/github.com/jackc/pgx/v5#Conn.CopyFrom), [goose upstream](https://github.com/pressly/goose): confirm APIs/tooling; code pins `pgx/v5 v5.13.0`. No new OSS recommended.
5. [Hysen Labs projects](https://hysenlabs.com/projects): reviewed directory as a discovery source; **no concrete independently verified immutable-content active-pointer implementation found**. No claim that the catalog proves the design. PostgreSQL transactional pattern is the relevant evidence.

## Additional review by requested area (1–8)

1. **Contract:** four migrations align with rev 1.1 names; global IDs, typed payloads, digest, rollback CAS are present. Divergences I-01, I-02, I-03 and unimplemented GC policy recorded above.
2. **Concurrency:** pointer→build lock order is explicit in [store.go:149–160](../../server/internal/content/store.go), `lockBuilds` uses `ORDER BY build_id FOR UPDATE`; Stage advisory locks hashtext(build_id), then build, no pointer. Trigger `FOR SHARE` [00004:8–19](../../server/migrations/00004_content_integrity_guards.sql) locks build on entity mutations. No definite lock-order inversion found for the provided API path; PostgreSQL lock waits/retry need real DB verification. Mid-transaction COPY error rolls back under pgx.BeginTxFunc; integration test [128–157](../../server/internal/content/store_integration_test.go) injects \u0000 late and asserts zero build/rows.
3. **Migrations/roles:** [roles script:6–17](../../deploy/newmmo/init/10-content-roles.sh) creates three roles; migrator owns migration objects; app SELECT-only; publisher column-granted writes. Table owner/migrator and superuser can disable ordinary triggers (trusted boundary). Publisher is not owner and cannot `ALTER TABLE ... DISABLE TRIGGER` or set `session_replication_role=replica` without elevated privilege; **actual role attributes/PG settings not queried**. Down drops registry in reverse order; production Down prohibited by contract.
4. **Bundle:** nested duplicate detection recursively walks JSON tokens; UTF-8/BOM, NaN/Infinity, limits and sorting covered. `readEntities` line-streams but accumulates decoded rows. Dirty input passing: noncanonical manifest with recalculated BUILD_ID; arbitrary hashed crossrefs. A valid JSON payload containing `\u0000` passes preflight but PostgreSQL jsonb COPY rejects it (integration test intentionally documents this), so `Verify` is **not** a guarantee of Stage success.
5. **Digest:** [store.go:248–263](../../server/internal/content/store.go) SQL formula matches [db-content.md:55–59](../contracts/db-content.md): `string_agg` ordered by kind/id, 0x1f fields, 0x1e rows, `payload::text`, `sha256(convert_to(...,'UTF8'))`; computed after COPY and compared at publish. SQL is source of digest; no Go-computed substitute. PostgreSQL JSONB text determinism across upgrades not tested.
6. **CLI:** [contentctl/main.go:33–114](../../server/cmd/contentctl/main.go) validates commands, errors return exit 1, no DSN printed; [store.go:360–378](../../server/internal/content/store.go) sanitizes DB errors. `publish` optional expected current defaults to empty, suitable only for first publish; `rollback` requires flag. No secrets observed in code.
7. **Compose/CI:** [compose.yml:1–33](../../deploy/newmmo/compose.yml) isolated `newmmo-dev`, loopback port, private network/volume, PG17 digest, env-required passwords; [ci.yml:47–106](../../.github/workflows/ci.yml) roles→goose as migrator→tests with publisher/migrator/app URLs; DB test skip grep exists. Issues I-04/I-05/I-10. CI uses `postgres:17` floating tag, not digest; Compose uses pinned digest.
8. **Dependencies:** [server/go.mod:1–13](../../server/go.mod) has **only** direct `pgx/v5 v5.13.0` and five approved indirect modules (`pgpassfile`, `pgservicefile`, `puddle/v2`, `x/sync`, `x/text`), no replace. `go.sum` hash verification and LICENSE files at pinned tags **not executed/independently rechecked**; approved licenses MIT/BSD are from [toolchain-pins](../contracts/toolchain-pins.md), not a new license audit.

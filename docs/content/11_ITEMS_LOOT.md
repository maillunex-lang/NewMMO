# LUNEX MMORPG — 11_ITEMS_LOOT.md
**Версия:** 1.0 | **Статус:** на утверждение | **Источник:** `01_WORLD.md`–`10_DIALOGUES.md` | **Следующий:** `12_DUNGEONS.md`.

> Полное техническое проектирование предметов и добычи для 6 регионов, 5 классов, 96 врагов, 12 подземелий, 240 заданий. Все числовые коэффициенты являются балансными гипотезами, не итоговыми значениями релиза. Не изменять репозиторий/VPS до отдельного указания.

## 1. Канон и границы системы
- Элиар, шесть регионов, уровень персонажа 1–60. Предметы усиливают выбранный класс, но не заменяют умения. Нет платной обязательной экипировки, выпадений с мирных NPC и добычи обязательных сюжетных предметов исключительно с мировых боссов.
- `ENM-*` только из `06_ENEMIES.md`; `MQ-*`/`SQ-*` только из утверждённых квестов. Никаких подмен названий и IDs.
- Пять классов: Страж (`CLS-01`), Берсерк (`CLS-02`), Маг (`CLS-03`), Следопыт (`CLS-04`), Оракул (`CLS-05`).
- Все выпадения, права владения, крафт, деньги, улучшения и награды рассчитывает Go-сервер. Godot лишь показывает подписанное сервером состояние.
- 6 типов редкости, 9 слотов, 2 типа привязки, 3 уровня доступа к луту (персональный, групповой, публичный ресурс).
- Основной сюжет про Печать Рассвета: Осколки Рассвета являются `QUEST_KEY`, не продаются, не уничтожаются, не выпадают случайно.

## 2. Словарь и реестр ID
| ID | Значение | Пример |
|---|---|---|
| `ITM-RR-NNN` | постоянный ID предмета | `ITM-01-001` |
| `MAT-RR-NNN` | ресурс/материал | `MAT-01-001` |
| `EQ-CC-RR-SS-RR` | экипировка класса CC, региона RR, слота SS, ранга RR | `EQ-01-01-MH-01` |
| `SET-CC-RR` | сет класса и региона | `SET-01-01` |
| `REC-RR-NNN` | рецепт крафта | `REC-01-001` |
| `LOOT-ENM-RR-NNN` | таблица добычи врага | `LOOT-ENM-01-001` |
| `DROP-...` | запись таблицы дропа | `DROP-ENM-01-001-A` |
| `ITEM-Q-RR-SS` | свидетельство основного квеста | `ITEM-Q-01-01` |
| `ITEM-SQ-RR-SSS` | свидетельство побочного квеста | `ITEM-SQ-01-001` |
| `ITEMINST-UUID` | экземпляр предмета в инвентаре | UUIDv7 |

**Важно:** `EQ` ID содержит `SS` из `MH/OH/HD/CH/HA/LG/FT/RG/AM`, последний `RR` - ранг предмета `01/02`; одинаковые значения RR в разных позициях имеют разный смысл. Для упрощения клиенту хранить структурные поля отдельно, не парсить ID регуляркой при выполнении.

Инвентарь 80 слотов, расширение только QoL; материалы в отдельном кармане 200 уникальных стеков, ограничение серверное.

## 4. Редкость, уровни и формулы
| Редкость | Цвет UI | Бонус к базовым статам | Аффиксы | Источники |
|---|---|---:|---:|---|
| COMMON | серый | 1.00 | 0 | старт, обычные враги |
| UNCOMMON | зелёный | 1.08 | 1 | обычные, ремесло |
| RARE | синий | 1.18 | 2 | элиты, ремесло, подземелья |
| EPIC | фиолетовый | 1.30 | 3 | боссы, сложные цепочки |
| LEGENDARY | золотой | 1.43 | 3 + эффект | редкие гарантированные коллекционные цепочки |
| MYTHIC | радужный | 1.55 | 4 + эффект | финальный прогресс и сложные достижения, не RNG-порог |

`item_level` привязан к региону и уровню: R1 1–10, R2 10–20, R3 20–30, R4 30–40, R5 40–50, R6 50–60. Требование уровня `required_level<=item_level`, допустимый разрыв не более 3.

**Базовая мощь:** `P = 8 + 2.4*item_level + 0.045*item_level²`; `stat_budget = round(P * rarity_mult * slot_mult)`, где mainhand=1.4, offhand=0.85, chest=1.25, head=0.9, hands=0.7, legs=1.0, feet=0.7, ring=0.55, amulet=0.65. Это бюджет распределения характеристик, НЕ готовый урон или защита.

**Распределение:** Страж 55% VIT, 30% DEF, 15% STR; Берсерк 50% STR, 30% CRIT, 20% VIT; Маг 55% INT, 25% HASTE, 20% VIT; Следопыт 50% DEX, 30% CRIT, 20% VIT; Оракул 55% WIS, 25% HASTE, 20% VIT. Конвертация в реальные AP/SP/HP/armor должна использовать единую модель `05_CLASSES.md`, не дублировать её.

**GS:** `sum(equipped_item_budget)` отображается как информационный показатель; никакой обязательной проверки GS для основного сюжета. PvP-нормализация отдельно, нельзя применять PvE-бюджет как PvP-урон.

## 7. Система аффиксов и улучшения
**Аффиксы:** `AFF-001` выносливость, `AFF-002` сила, `AFF-003` интеллект, `AFF-004` ловкость, `AFF-005` мудрость, `AFF-006` шанс крита, `AFF-007` скорость применения, `AFF-008` броня, `AFF-009` сопротивление, `AFF-010` эффективность исцеления, `AFF-011` блок, `AFF-012` восстановление ресурса. Серверная генерация из whitelist по классу/слоту; запрет неподходящих (например, лечение на чисто физическом оружии без гибридного свойства).

**Заточка +0..+10:** +1..+5 без риска потери, +6..+10 с затратой катализатора; неудача не уничтожает предмет и не уменьшает уровень, только расходует материалы; шансы успеха [100,100,100,100,100,80,70,60,50,40]%, но с защитой от невезения: после 3 неудач следующая гарантирована. Бонус каждого уровня +1.5% к базовому бюджету, максимум +15%.

**Перековка:** заменяет только один аффикс; цена растёт на 20% при повторных попытках и сбрасывается после 5 попыток, чтобы исключить бесконечную инфляцию. Результат генерируется сервером, перед подтверждением клиент видит стоимость и последствия.

**Разбор:** 40–60% базовых материалов по региону, без возврата катализаторов; привязанные предметы дают привязанные материалы, чтобы не отмывать рынок. Запрещён разбор предметов с флагом `locked` или в активной торговле.

## 13. Сбор ресурсов и PvP
- Узлы `RES-RR-001..003` серверные: ресурсная точка имеет `node_instance_id`, состояние `available/depleted/respawning`, персональный 3-секундный канал сбора с проверкой дистанции и line-of-sight.
- Один успешный сбор: 1–3 единицы `MAT-RR-001..003`; повторная выдача по тому же `harvest_event_id` запрещена. Респавн 3–7 минут с разбросом; не блокирует основные квесты.
- PvP-смерть: **не выбрасывает экипировку, квестовые предметы, валюту или материалы**; награда PvP определяется отдельным документом. Убитый игрок не становится контейнером для грабежа.
- Групповые награды персональны. Торговля между игроками допустима только для `UNBOUND` и неактивных в квесте предметов; серверная двойная блокировка обоих инвентарей предотвращает дюпы.

### PostgreSQL: сущности и ограничения
```sql
CREATE TABLE item_templates (id text PRIMARY KEY, kind text NOT NULL, payload jsonb NOT NULL, revision int NOT NULL DEFAULT 1);
CREATE TABLE item_instances (id uuid PRIMARY KEY, template_id text NOT NULL REFERENCES item_templates(id), owner_character_id uuid NOT NULL, quantity int NOT NULL CHECK (quantity>0), bind_state text NOT NULL, enhancement int NOT NULL DEFAULT 0 CHECK (enhancement BETWEEN 0 AND 10), rolled_affixes jsonb NOT NULL DEFAULT '[]'::jsonb, locked boolean NOT NULL DEFAULT false, version bigint NOT NULL DEFAULT 0);
CREATE INDEX idx_item_owner ON item_instances(owner_character_id);
CREATE TABLE currency_ledger (id uuid PRIMARY KEY, character_id uuid NOT NULL, currency text NOT NULL, delta bigint NOT NULL, source_event_id text NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), UNIQUE(character_id,currency,source_event_id));
CREATE TABLE loot_claims (character_id uuid NOT NULL, source_event_id text NOT NULL, loot_table_id text NOT NULL, reward_payload jsonb NOT NULL, claimed_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY(character_id,source_event_id));
CREATE TABLE crafting_jobs (id uuid PRIMARY KEY, character_id uuid NOT NULL, recipe_id text NOT NULL, state text NOT NULL, finish_at timestamptz NOT NULL, idempotency_key text NOT NULL UNIQUE);
CREATE TABLE inventory_audit (id bigserial PRIMARY KEY, character_id uuid NOT NULL, event_id text NOT NULL, action text NOT NULL, payload jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now());
```

Миграции согласовать с существующей схемой проекта: SQL здесь **логический контракт**, не запускать без проверки уже существующих таблиц. Уникальный индекс `(owner_character_id,slot)` для экипированных предметов в отдельной таблице.

| `inventory.equip` | instance_id, target_slot, request_id | new_inventory_version, stat_snapshot |
| `inventory.unequip` | instance_id, request_id | new_inventory_version |
| `loot.claim` | source_event_id, request_id | loot_claim_id, rewards |
| `craft.start` | recipe_id, count, request_id | craft_job_id, finish_at |
| `craft.claim` | craft_job_id, request_id | delivered_items |
| `item.enhance` | instance_id, request_id | new_level, materials_spent |
| `item.salvage` | instance_id, request_id | materials_received |
| `trade.offer` | partner_id, instance_ids, gold, request_id | escrow_id, status |

**Порядок:** проверка авторизации → ownership → level/class/slot → optimistic version → row locks → atomic changes → audit log → commit → ответ. Каждое действие принимает `request_id` (UUID), повтор возвращает тот же результат; клиенты не передают итоговый урон, шансы, качество, баланс или сумму вознаграждения.

## 15. Антидюп, безопасность и наблюдаемость
- Атомарность начисления квестовой награды, золота, предметов и статуса задания; если один этап неуспешен, вся транзакция откатывается.
- RNG: криптографически стойкий PRNG сервера, весовые таблицы с версией `loot_revision`; аудит `seed_commit`/хэш-следа без раскрытия будущих результатов игроку.
- Лимиты: 10 `loot.claim`/с на аккаунт, 4 `craft.start`/с, 4 торговых операции/с; превышение - временный отказ без изменения данных.
- Защита от race conditions: `SELECT ... FOR UPDATE` для расходуемых стеков, ledger, обмена; уникальные ключи событий и внешние ключи.
- Наблюдаемость: `loot_roll_total`, `loot_claim_duplicates_total`, `inventory_transaction_failures`, `currency_minted_gold`, `currency_sunk_gold`, `craft_completion_latency`, `market_trade_volume`.
- Логи без персональных токенов и паролей. Админка React+TS показывает каталоги и историю изменений с RBAC и журналом действий; редактирование вероятностей через ревизии с предпросмотром и откатом.

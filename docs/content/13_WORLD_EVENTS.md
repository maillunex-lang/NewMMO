# LUNEX MMORPG — 13_WORLD_EVENTS.md
**Версия:** 1.0 | **Статус:** проект для утверждения | **Охват:** 6 регионов, 18 событий, 6 мировых боссов
**Зависимости:** `01_WORLD.md`–`12_DUNGEONS.md`. **Следующий документ:** `14_CONTENT_INTEGRATION.md`.

> События не переписывают общий сюжет, не заменяют главные квесты и не требуют обязательного убийства мирового босса для завершения кампании. Все награды и результаты вычисляет авторитетный Go-сервер. Числа баланса ниже — стартовые настройки, а не проверенные метрики.

## 1. Границы и источники истины
- `EVT-RR-001`: дорожное/экспедиционное событие; `EVT-RR-002`: региональная аномалия; `EVT-RR-003`: мировой босс `ENM-RR-401`. `RR=01..06`.
- `LOC-RR-004`: опасная дорога, `LOC-RR-005`: сюжетный узел. Публичная арена босса создаётся внутри `LOC-RR-004` как отдельная подзона `ARENA-EVT-RR-003`, а не внутри сюжетного узла. `POI-RR-004`: дорожный маркер; `POI-RR-005`: маркер узла. Не менять географию из `03_LOCATIONS.md`.
- Уровни регионов: 01=1–10, 02=10–20, 03=20–30, 04=30–40, 05=40–50, 06=50–60. Для публичных боссов рекомендуемый уровень 10/20/30/40/50/60. Игроки ниже рекомендованного уровня могут наблюдать, но не обязаны участвовать.
- Фракции `FAC-01..08`, персонажи `NPC-...`, враги `ENM-...`, лут `LOOT-...`, ресурсы и материалы должны резолвиться в единый контентный реестр. Если предмета нет в `11_ITEMS_LOOT.md`, вводится отдельная виртуальная событийная валюта без боевых характеристик, с регистрацией в `14_CONTENT_INTEGRATION.md`.
- События публичны для канала/шарда, но прогресс, награды и сюжетные выборы персональны. PvP не разрешается внутри `ARENA-EVT-*` и в защитной полосе эвакуации, даже если окружающая зона `CONTESTED`; снаружи действуют правила зоны.
- Система времени: сервер хранит UTC; расписание показывается в локальном времени клиента. Ежедневный сброс по UTC 03:00 (настраиваемое значение), но нельзя сбрасывать активную попытку. Расписания конфигурируемые, без жёстких дат в коде.

## 3. Публичный цикл и игровые правила
### 3.1 Состояния
`SCHEDULED -> ANNOUNCED -> PREPARING -> ACTIVE -> SUCCESS/FAILED/TIMED_OUT -> REWARD_LOCKED -> COOLDOWN -> SCHEDULED`. Отмена администратором: `CANCELLED`, с компенсацией только подтверждённых расходов, без выдачи победных наград. Переходы атомарны, только сервером.
### 3.2 Общий тайминг (настройки по умолчанию)
| Тип | Анонс | Подготовка | Активная фаза | Период | Предел игроков канала |
|---|---:|---:|---:|---|---:|
| `001` | 5 мин | 2 мин | 12 мин | каждые 90 мин на регион | 40 |
| `002` | 8 мин | 3 мин | 15 мин | каждые 150 мин на регион | 40 |
| `003` | 15 мин | 5 мин | 20 мин | 3 раза в сутки на регион, интервалы не менее 6 ч | 50 |
Время регионов сдвигается детерминированным seed, чтобы сервер не запускал 18 событий одновременно. Админка может менять расписание, но изменение версии не отменяет уже объявленное событие. При отсутствии игроков событие всё равно завершается по таймеру, без бесплатных наград.
### 3.3 Участие, масштабирование и доступность
- Вход через публичный маркер или область, без очереди для `001/002`. Для босса канал фиксирует список участников при входе в арену, допускает поздний вход до фазы 3. Если заполнен, открывается дополнительная независимая копия арены в том же шарде; не создаются новые мировые убийства в одном экземпляре.
- Коэффициент HP для целей и боссов: `min(3.0, 1 + 0.12 * max(0, active_participants-5))`, пересчитывается только на границах фаз, без лечения уже полученного урона. Урон босса масштабировать не выше 1.35; не усиливать контроль от числа игроков.
- Для событий `001/002` нормировать объём объектов по числу участников: `target = min(30, 6 + 2*active_participants)`, не менять после начала стадии; каждому игроку доступен индивидуальный вклад.
- Вклад учитывает урон по цели, исцеление реально потерянного HP, предотвращённый урон, взаимодействия с механизмами, доставку груза и спасение NPC. AFK, самоисцеление на полном HP, повторный клик и нанесение урона своим объектам не дают вклад.
- Слабый Android: сервер отдаёт полную симуляцию, клиент рисует не более выбранного лимита видимых участников, остальные как компактные маркеры; LOD VFX, объединение телеграфов, 30 FPS цель, без скрытия опасных зон.
### 3.4 Распределение наград
- Успех: участие >= 60 секунд, вклад >= 100 очков (настраивается), минимум одно значимое действие за последние 180 секунд. Для поддержки отдельные коэффициенты, чтобы хилеры/танки не проигрывали DPS.
- Ранг участия: Bronze 100–249, Silver 250–499, Gold >=500. Ранг меняет только размер персональной награды, не право на сюжет или предметы первой необходимости. Персонаж получает не более одного комплекта наград за `instance_id`.
- Событийные жетоны `TOK-EVT-RR` (виртуальный баланс, не предмет инвентаря) 1/2/3 за Bronze/Silver/Gold для `001/002`, 3/5/7 для `003`. Ограничение 35 жетонов на регион в календарную неделю, сброс UTC понедельник 03:00. Переизбыток не конвертировать в золото.
- Золото и XP: `001`: 60% базовой награды главного задания региона, `002`: 75%, `003`: 100%; повторное прохождение в пределах суток даёт 20% XP/золота, но жетоны сохраняются в недельном лимите. Базовые награды брать из утверждённого баланса `08_QUESTS_MAIN.md`, не дублировать цифры в клиенте.
- Редкий дроп босса по `LOOT-ENM-RR-401` из `11_ITEMS_LOOT.md` только при первом квалифицированном успешном прохождении в сутки на персонажа; последующие победы дают жетоны/пониженные XP. Лут персональный, ролл серверный с аудируемым seed. Никаких предметов из инвентаря другого игрока.
- При провале выдаётся только утешительная награда (до 20% XP) за подтверждённые действия, без босcового дропа, жетонов победы или репутации. Досрочный выход сохраняет вклад до завершения экземпляра; награда отправляется в почту только после успешного завершения.

## 4. Полные сценарии 18 событий

### REG-01 — Долина Рассвета
**Канон:** Астервиль, `FAC-01`, координатор `NPC-102`, второй свидетель `NPC-801`. Дорожная зона `LOC-01-004`, сюжетная граница `LOC-01-005`; стартовые маркеры `POI-01-004/005`. Все сценарии могут повторяться без изменения основных флагов `QF-MQ-*`.

#### `EVT-01-001` — «Караван снабжения: маршрут без гарантий»
**Логлайн:** из Астервиль выходит караван снабжения; на участке «Исчезнувший тракт» обычная перевозка превращается в проверку, существует ли дорога в документах. Сатира: чиновник требует акт о том, что обоз не исчезал, до того как обоз прибыл.
**Старт:** `REG-01` открыт для игрока по уровню, `LOC-01-004` загружен; NPC `NPC-102` объявляет сбор. **Серверные флаги:** `EF-EVT-01-001-ANNOUNCED`, `...-ACTIVE`, `...-SUCCESS`, `...-FAILED` (суффикс относится к `instance_id`, не глобальный флаг персонажа).
**Фазы и точные цели:**
1. `PH-EVT-01-001-01` (180 с): собрать 6 дорожных свидетельств `печати накладных` у 3 объектов `OBJ-EVT-01-001-01..03`, зарегистрировать минимум 3 уникальных взаимодействия всей группы. Пока нет 3, обоз не трогается.
2. `PH-EVT-01-001-02` (360 с): сопровождать `ACTOR-EVT-01-001-CONVOY` через 3 серверных чекпоинта `CP-EVT-01-001-01..03`. Скорость 2.5 условных единицы/с, пауза при нападении, HP обоза 1000 базовых единиц с масштабированием; провал при HP=0. Появляются 2 волны из `SPAWN-01-001` и `SPAWN-01-002`, только обычные враги региона `ENM-01-001..008`.
3. `PH-EVT-01-001-03` (180 с): у конечного моста устранить 3 помехи `дорожные указатели` (`OBJ-EVT-01-001-04..06`) и сохранить не менее 1 HP обоза; одновременно третья волна `SPAWN-01-003`. Успех при всех трёх объектах и достижении конечного чекпоинта.
**Ветвление:** игроки голосуют у `NPC-102` за `EVCHOICE-01-001-A` «короткая дорога» (одна усиленная волна, +10% итогового XP) либо `...-B` «объезд» (дополнительные 90 с пути, +10% к HP обоза). Голосование 30 с, один голос на персонажа, ничья => B. Выбор действует только на текущий экземпляр, не меняет канон.
**Реплики:** `NPC-102`: «Если груз не дошёл, прошу не оформлять это как досрочную доставку». Ответ игрока A: «Проверю дорогу, не только печать». B: «Сначала проверим, существует ли получатель». **Показывать:** `ACTIVE`, игрок в радиусе 20 м и не в бою; текст не блокирует движение.
**Награды:** базовая таблица `REWARD-EVT-01-001`, жетоны `TOK-EVT-01`, репутация `FAC-01` +3 при первой победе за сутки; без уникального обязательного предмета. **Отказоустойчивость:** при застревании NPC >15 с сервер перестраивает маршрут до ближайшего CP, не телепортирует обоз через стену.

#### `EVT-01-002` — «Письма, пришедшие раньше отправителя»
**Логлайн:** на границе узла проявляется «запоздалый звон». `NPC-801` просит локализовать аномалию, не уничтожая исторические свидетельства. Сатира: акт осмотра подписан сразу двумя несовместимыми датами.
**Старт:** `LOC-01-005` доступен, активность объявлена на карте; вход с `POI-01-005` в отдельную публичную область `AREA-EVT-01-002`, сюжетный узел не изменяется. **Флаги:** `EF-EVT-01-002-PHASE-1/2/3`, `...-STABILIZED`, `...-FAILED`.
**Фазы и точные цели:**
1. `PH-EVT-01-002-01` (240 с): сканировать 4 нестабильных маркера `OBJ-EVT-01-002-01..04`, каждое сканирование 5 с, прерывается уроном. Сканировать могут разные игроки, один объект засчитывается один раз для экземпляра.
2. `PH-EVT-01-002-02` (360 с): собрать 12 единиц `печати накладных` из точек `NODE-EVT-01-002-01..06`, удерживая не менее двух из трёх стабилизаторов `дорожные указатели` в активном состоянии; враги из `SPAWN-01-003/004`, не мировой босс.
3. `PH-EVT-01-002-03` (240 с): синхронизировать три стабилизатора в последовательности `1-3-2`, сервер проверяет окно 12 с между активациями; ошибка сбрасывает только последовательность, не весь прогресс. После трёх успешных нажатий требуется 45 с обороны.
**Особая механика региона:** запоздалый звон создаёт 2–4 видимые безопасные дорожки, телеграф 2.5 с, интервал 12 с; урон не выше 25% базового HP персонажа за одно попадание, без неразличимого мгновенного поражения.
**Решение:** `EVCHOICE-01-002-A` сохранить исторический отпечаток (дополнительная запись в личном журнале), `...-B` очистить аномалию (дополнительные 2 жетона один раз на аккаунт за регион). Оба пути завершают событие; голосование 30 с, ничья => A. Нельзя открывать закрытые сведения кампании до сюжетного допуска.
**Реплики:** `NPC-801`: «У нас две версии произошедшего. Прошу не складывать их в одну папку». Ответ A: «Сохраним обе». Ответ B: «Сначала спасём тех, кто здесь». **Награды:** `REWARD-EVT-01-002`, `TOK-EVT-01`, репутация `FAC-01` +4 за первую победу в сутки.

#### `EVT-01-003` — «Колокол Несуществующего Полудня»
**Сущность:** `ENM-01-401` «Колокол Несуществующего Полудня», уровень 10, существующие фазы и умения `AB-ENM-01-401-*` из `06_ENEMIES.md` обязательны. **Локация:** `ARENA-EVT-01-003` внутри `LOC-01-004`; отдельная инстанс-копия на группу канала, без изменения `LOC-01-005`. **Лут:** `LOOT-ENM-01-401` из `11_ITEMS_LOOT.md`.
**Анонс:** `NPC-102` объявляет опасность, карта показывает `POI-01-004`, время старта и текущую заполняемость. **Подготовка 300 с:** игроки активируют три защитных устройства `дорожные указатели` `OBJ-EVT-01-003-01..03`; каждое даёт группе -5% к урону первой массовой атаки (максимум -15%). Подготовка не является обязательной для появления босса.
**Бой:** `PH-EVT-01-003-01` HP 100–75%, `...-02` 75–40%, `...-03` 40–0%. Умения, атаки, время предупреждения и механики фазы наследуются из `06_ENEMIES.md`, **не дублируются новыми значениями**. Все дополнительные серверные цели имеют только вспомогательный характер.
**Цели поддержки:** в фазе 2 обезвредить 3 якоря `OBJ-EVT-01-003-04..06` (каждый ослабляет следующую АоЕ на 10%, максимум 30%); в фазе 3 спасать павших союзников или поддерживать защитный круг. Нельзя ставить новые механики, противоречащие индивидуальной фазовой спецификации босса.
**Условия успеха:** сервер зафиксировал `boss_hp <= 0`, `instance_state=ACTIVE`, `kill_event_id` уникален; засчитать персональную награду при достаточном вкладе. **Провал:** таймер 1200 с, все участники покинули арену >120 с или админ-отмена; при смерти игрок может вернуться через контрольную точку с 20-секундным дебаффом на повторный вход, без потери уже заработанного вклада.
**Реплика:** `NPC-801`: «Пожалуйста, не вписывайте победу в отчёт до окончания сражения. В прошлый раз это обидело саму реальность». **Награды:** `REWARD-EVT-01-003` + `LOOT-ENM-01-401` по лимитам, `FAC-01` +6 репутации при первой победе за сутки. **Флаги:** `EF-EVT-01-003-SPAWNED`, `...-PHASE-2`, `...-PHASE-3`, `...-KILLED`, `...-FAILED`.
**Тестовые критерии:** нельзя убить `ENM-01-401` дважды в одном экземпляре; два клиента видят одинаковые фазы; опоздавший игрок не получает награду без вклада; при потере связи HP босса не откатывается; сервер сохраняет лут ровно один раз.

```sql
CREATE TABLE IF NOT EXISTS world_event_templates (
  event_id text PRIMARY KEY, region_id text NOT NULL, content jsonb NOT NULL,
  schema_version integer NOT NULL CHECK (schema_version > 0), enabled boolean NOT NULL DEFAULT true);
CREATE TABLE IF NOT EXISTS world_event_instances (
  instance_id uuid PRIMARY KEY, event_id text NOT NULL REFERENCES world_event_templates(event_id),
  channel_id text NOT NULL, schedule_version integer NOT NULL, status text NOT NULL,
  starts_at timestamptz NOT NULL, ends_at timestamptz NOT NULL,
  phase_id text, phase_started_at timestamptz, state jsonb NOT NULL DEFAULT '{}'::jsonb,
  version bigint NOT NULL DEFAULT 0, updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (event_id, channel_id, starts_at));
CREATE TABLE IF NOT EXISTS world_event_participants (
  instance_id uuid NOT NULL REFERENCES world_event_instances(instance_id),
  character_id bigint NOT NULL, contribution integer NOT NULL DEFAULT 0,
  first_joined_at timestamptz NOT NULL DEFAULT now(), last_action_at timestamptz,
  reward_rank text, PRIMARY KEY(instance_id, character_id));
CREATE TABLE IF NOT EXISTS world_event_actions (
  instance_id uuid NOT NULL, action_id uuid NOT NULL, character_id bigint NOT NULL,
  action_type text NOT NULL, accepted_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY(instance_id, action_id));
CREATE TABLE IF NOT EXISTS world_event_rewards (
  instance_id uuid NOT NULL, character_id bigint NOT NULL, reward_payload jsonb NOT NULL,
  claimed_at timestamptz, created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY(instance_id, character_id));
CREATE TABLE IF NOT EXISTS world_event_token_balances (
  character_id bigint NOT NULL, region_id text NOT NULL, week_start_utc timestamptz NOT NULL,
  earned integer NOT NULL DEFAULT 0 CHECK (earned BETWEEN 0 AND 35),
  PRIMARY KEY(character_id, region_id, week_start_utc));
CREATE INDEX IF NOT EXISTS idx_world_event_instances_active ON world_event_instances(status, ends_at);
CREATE INDEX IF NOT EXISTS idx_world_event_participants_char ON world_event_participants(character_id);
```
**Миграционная оговорка:** `character_id bigint` — пример; адаптировать к реальному типу PK проекта. Связь `world_event_actions.instance_id` можно оформить FK после проверки партиционирования/retention. Платёжные операции и начисления проводить в одной транзакции с записью `world_event_rewards`, с `ON CONFLICT DO NOTHING` и проверкой результата, а не отдельными запросами без блокировки.

| Событие | Направление | Поля | Правило |
|---|---|---|---|
| `world_event.snapshot` | S→C | `instance_id,event_id,status,phase_id,ends_at,version,objectives` | при входе и reconnect |

### 7.5 Псевдокод перехода
```go
func ApplyEventAction(tx Tx, instanceID UUID, actor CharacterID, action Action) error {
    instance := tx.LockInstance(instanceID)
    if !instance.IsActive() || !ValidateActor(instance, actor, action) { return ErrInvalidAction }
    if tx.ActionExists(instanceID, action.ID) { return nil } // idempotency
    if !ValidatePhaseObjective(instance, action) { return ErrInvalidObjective }
    tx.InsertAction(instanceID, actor, action)
    instance.ApplyServerValidated(action)
    if instance.PhaseComplete() { instance.AdvancePhase() }
    tx.SaveInstanceVersioned(instance)
    return tx.Commit()
}
```

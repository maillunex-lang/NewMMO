# T-016 — руководство по стилю диалогов и спецификация линта

**Статус:** исследовательская рекомендация, не канон. Согласовать с директором до EX-CONTENT-01. Никаких изменений `docs/content/**`.

## 1. Художественная норма: стиль A

Серьёзное фэнтези, где мир и цена спасения реальны; институциональный сарказм направлен на канцелярии, формы и самоуверенные протоколы, **никогда** на раненых, погибших и лишённых памяти. Тон задают `01_WORLD`/`07_STORY`, образец исполнения: утверждённые `dialogue_expansion/MQ-01-01…04`. До главы IV запрещено раскрывать цену Договора или утверждать устройство шестого узла как «шестого хранителя».

**Голос:** каждый NPC имеет цель, профессиональный словарь, страх/уязвимость, отношение к другим и собственный ритм речи из `04_CHARACTERS`. Фейра говорит измерениями, нетерпелива к ошибкам; Ильра требует проверяемых фактов и бережёт пострадавших; Орин мыслит дорогами и следами. Не заменять это общей фразой «доказательство важнее объяснения». Нэвиар (NPC-501) общается письменно/рунами, никогда не озвучивается.

**Длина:** NPC 35–160 символов целево, предупреждение >180, ручной обзор >240; PLAYER 12–90, предупреждение >110; SYSTEM 12–120, предупреждение >140. Для длинной речи разделить по естественным паузам, не склеивать строковые фрагменты. Один смысловой поворот на реплику, максимум два предложения по умолчанию. Длина измеряется Unicode code points, без ID и метаданных. Порог является редакционным, не техническим ограничением UI.

**Сцена:** START = наблюдаемая деталь + личный мотив + запрос, не копия журнала; PLAYER `ASK` возвращает в ту же сцену без флага, `ACCEPT` переводит AVAILABLE→ACTIVE только через сервер, `LATER` закрывает без принятия. OBJ1–3: до выполнения только подсказка о следующем действии, после подтверждённого события реакция на конкретную улику; PROGRESS отдельные варианты для 0/1/2 целей, при трёх целях переход к TURNIN. TURNIN = предъявление подтверждённого результата, доступно только `objectives_complete`; DONE = эмоциональное последствие и новая сюжетная перспектива, не повторная награда. CHOICE только при утверждённом A/B или финальном тройном исходе, все пути сходятся в безопасную точку без нового обязательного квеста.

**Ответы:** `ACCEPT` = намерение принять, `ASK` = осмысленное уточнение о риске/мотиве/улике, `LATER` = вежливая отсрочка, `CONTINUE` = продолжить сцену, `TURN_IN` = предъявить результат; выбор A/B = описать конкретное действие и последствие, не «вариант A». Никакая текстовая кнопка не выдаёт награду. Избегать ложной срочности при повторяемом контенте.

**Запрещённые шаблоны для авторской сдачи:** «Я проверю это. Что требуется в первую очередь?», «Проверю это на месте», «Теперь есть с чем сравнить», «Зафиксирую результат без догадок», «Задание выполнено. Вот подтверждённые результаты», «Пока не все свидетельства собраны», «Есть продвижение, но дело ещё не закрыто», «Хорошо, что на этот раз факты дошли до адресата», «Теперь мы знаем больше, чем до начала расследования», «На бумаге всё выглядит просто». Не запрещать обычные слова «дорога», «печать», «факт» по отдельности: только механические конструкции и семантические повторы.

**SYSTEM:** нейтральная и короткая проверяемая команда, содержит объект/количество/условие, не художественную эмоцию и не секрет. Стадия OBJ-хинта должна соответствовать серверной активной цели, а не следующему шагу. Не выдавать факт успеха до `objective_event`.

**Локализация:** одна реплика = один устойчивый `DIA.*` и локализационный ключ, не конкатенировать строки и не менять ID при переводе; не хардкодить пол/падеж игрока, предпочитать нейтральную конструкцию или локализуемые полные варианты; переменные с грамматическими категориями только по утверждённой схеме; поддерживать плейсхолдеры и их типы; проверять расширение текста в UI на Android и разрывы строк, не вставлять ручные `\\n` ради конкретной ширины. Никаких гендерных догадок о персонаже игрока.

**Граф:** сохранять существующие `DIA.*`, quest ID, NPC, локации, 3 objective ID, награды и QF/SQF/SQC/CHOICE флаги; добавлять `.04`, `.05` рядом, без массового ренейма. Любой `ASK` и `LATER` возвращает к безопасному узлу; `ACCEPT`, `choose`, `turn_in`, `claim_reward` идемпотентны и валидируются сервером. Показ `DONE` не равен выплате `REWARD`. Не вводить NPC-ID для эпизодической роли без согласования.

## 2. Самопроверка автора

- [ ] Сверены `07` (доступное знание), `08/09` (три цели/результат/ветки), `04` (голос), утверждённый пилот.
- [ ] START не является журналом, NPC отличается от других без имени в подписи.
- [ ] На каждом OBJ есть до/после при необходимости; PROGRESS отражает 0/1/2 цели.
- [ ] У START есть смысловые ACCEPT/ASK/LATER; при выборе проверены A/B и финальные END.
- [ ] Нет спойлера до IV, шутки не направлены на жертв.
- [ ] Ни одна строка не изменяет состояние сама, все ветки достижимы и имеют выход.
- [ ] Не менялись ID, флаги, награды, NPC, локализационные ключи; текст помещается на Android.

## 3. Спецификация автоматического линта (предложение директору)

| Код | Проверка | Порог / уровень | Пример срабатывания |
|---|---|---|---|
| DIA-ID | regex `^DIA\\.(MQ-\\d{2}-\\d{2}\\|SQ-\\d{2}-\\d{3})\\.(START\\|PROGRESS\\|OBJ[123]\\|TURNIN\\|DONE\\|CHOICE)\\.\\d{2}$`, уникальность | ERROR на любое нарушение | `DLG-*`, повтор ID |
| DIA-STAGE | START/OBJ1/OBJ2/OBJ3/PROGRESS/TURNIN/DONE у каждого квеста | ERROR если отсутствует | нет `OBJ2` |
| DIA-SPEAKER | NPC ID соответствует контакту/разрешённому участнику 08/09, PLAYER/SYSTEM разрешены | ERROR для неизвестного NPC, WARN для иного известного | `NPC-999` |
| DIA-EXACT | нормализация пробелов, кавычек, регистра; подсчёт совпадений в NPC+PLAYER | WARN ≥3 квестов; ERROR ≥8, кроме утверждённого allowlist | «Я проверю это…» 120 |
| DIA-NEAR | 3-граммы слов Jaccard ≥0.82 или Levenshtein similarity ≥0.90, текст ≥25 символов | WARN пара ≥0.82 в разных квестах, ERROR кластер ≥8 | DONE с одним и тем же хвостом |
| DIA-LENGTH | code points NPC >180, PLAYER >110, SYSTEM >140 | WARN; >240/>160/>200 ERROR на ревью | START с копией журнала |
| DIA-JOURNAL | overlap 5-грамм START с полем журнала 08/09 | WARN ≥0.50, ERROR ≥0.80 при длине ≥60 | `MQ-01-01.START.01` |
| DIA-PROGRESS | как минимум 2 разных guards 0/1/2 выполненных цели | WARN пока формат не описывает guards, затем ERROR | `PROGRESS.01` один на квест |
| DIA-CHOICE | ветки для 08 CHOICE-RR-09/20 и 06-FINAL; для 09 `SQC` | ERROR при отсутствии канонического выбора после согласования mapping | `MQ-01-20` |
| DIA-SECRET | маркеры `цен* Договор*`, `плат* память*`, `шест* хранител*`, `жертв* память*` в главах I–III | ERROR для точных раскрытий, WARN на `Договор`+`память` в контексте | раннее прямое объяснение цены |
| DIA-PUNCT | терминальная точка/!?/…/закрывающая кавычка; без повторных !!! | WARN, исключения для обрывов речи | «Проверка завершена» без знака |
| DIA-LOC | ID локализации существует 1:1, плейсхолдеры совпадают по языкам | ERROR | отсутствующий переводный ключ |
| DIA-STATE | статический guard для TURNIN/DONE, OBJ реакций, ACCEPT/ASK/LATER; проверка достижимости | ERROR на недостижимую ветку/невалидный флаг, WARN на неявный guard | OBJ2 «Теперь есть с чем сравнить» до события |
| DIA-VOICE | частота общих клише NPC и совпадение профессиональной лексики | WARN редактору, не автопровал | одинаковый PROGRESS у Фейры и Ильры |

Выполнение: парсинг `10` → связка с декларациями `08/09/04` → текстовые метрики → графовые проверки → JSON-отчёт по ID с `severity, rule, evidence, expected, actual`; baseline существующих 240 квестов и дифф только изменённых квестов для батчей. Не включать новый линт в CI без решения директора, чтобы старый канон не стал внезапно красным. Нужен отдельный тест на ложные срабатывания и исключения с объяснением, сроком и владельцем.

## 4. Research-first: источники и переносимые идеи

1. **Yarn Spinner**, https://yarnspinner.dev/docs/ и https://github.com/YarnSpinnerTool/YarnSpinner : узлы, стабильные line IDs, опции, проверки компиляции и локализация. Перенести проверку адресуемости узлов и сохранности ключей, не зависимость. Open source, MIT; активная документация 2026, совместимость с Godot зависит от интеграции; Android не требует runtime Yarn при собственном линте.
2. **inkle ink**, https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md : knots/stitches, условные choices, предупреждение о «loose ends», тестирование путей. Перенести проверку достижимости/терминальных состояний и автоматический обход сценариев; не компилятор. Open source MIT, актуальная документация; не предполагается перенос runtime на Android.
3. **Dialogue Manager (Nathan Hoad)**, https://store.godotengine.org/asset/nathanhoad/dialogue-manager/ : синтаксическая диагностика, тестовая сцена, переводы, stateless runtime. Перенести диагностику и разделение текста от авторитетного сервера; не ставить аддон. MIT (см. upstream), страница указывает Godot 4.6+, пригодность к Android не тестировалась.
4. **Hysen Labs**, https://hysenlabs.com/projects : каталог проверен как исследовательский адрес из задания, но в текущем поиске не удалось надёжно извлечь конкретную карточку проекта с лицензией/активностью; **не выдавать** это за подтверждённый кандидат.

**Рекомендация:** собственный stdlib-линт на существующем экспортном формате, без новой зависимости. Лицензии/активность указаны ориентировочно по публичным upstream-страницам; перед выбором стороннего инструмента директор должен проверить точный LICENSE и последние релизы.

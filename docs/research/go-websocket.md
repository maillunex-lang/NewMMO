## 4. Godot 4.x / Android

`WebSocketPeer` — встроенный клиент, без GDScript-аддона: `connect_to_url()`, `poll()`, `get_ready_state()`, `get_available_packet_count()`, `get_packet()`, `put_packet()`, `send_text()`, `close()`, `get_close_code()`, `get_close_reason()`, `get_requested_url()`. Text и binary payload поддерживаются; **один WebSocket message = одно прикладное сообщение**, не считать TCP фреймы границами сообщений. [Godot 4.3 class](https://docs.godotengine.org/en/4.3/classes/class_websocketpeer.html), [tutorial](https://docs.godotengine.org/en/4.3/tutorials/networking/websocket.html), [RFC6455 §5](https://www.rfc-editor.org/rfc/rfc6455#section-5).

`poll()` обязателен регулярно (обычно `_process`), иначе control frames/закрытие и входящие сообщения не обрабатываются вовремя. На Android проверять pause/resume, смену Wi-Fi/LTE, тайм-ауты, фоновое ограничение ОС, два одновременных касания и reconnect; точные регрессии Godot 4.3/4.7.2 на Android **не проверены**. Ping/pong по RFC — transport control; не предполагать, что GDScript предоставляет произвольный raw Ping API. Godot может отвечать на Ping внутри `poll()`; конкретный режим сжатия/permessage-deflate и negotiation с coder на Godot Android **не проверены**. **Старт: без компрессии**, без обязательных extensions, только `wss://` в публичном окружении, сертификат и hostname валидируются. Не требовать от Godot пользовательских HTTP headers, пока не проверена поддержка точной версии API; безопасный вариант — короткоживущий одноразовый ticket, выданный HTTPS, в первом сообщении после upgrade с ограниченным pre-auth временем. Не передавать bearer в URL query (логи). [RFC6455 §10](https://www.rfc-editor.org/rfc/rfc6455#section-10).

**Рекомендация:** JSON текстовые WS сообщения на первом этапе. Переход на бинарный — только по профилю: bytes/sec, p95 decode, allocations, мобильная батарея и память на 6 ГБ. Не менять формат внутри той же protocol major без negotiation.

### Предлагаемая оболочка (не утверждённый контракт)

`{ "protocol_version": 1, "type": "quest.accept.request", "request_id": "uuid", "session_id": "...", "trace_id": "...", "revision": "42", "server_time": "...", "payload": { "quest_id": "MQ-01-01", "content_build_id": "..." } }`.

В §15.2 канон требует `protocol_version, session_id, server_time, revision, trace_id` у каждого сообщения. **Конфликт/уточнение для директора:** клиент не должен выбирать `session_id`, `server_time` или `revision` как авторитетные. Для C→S либо разрешить пустые/null значения, либо разделить обязательные поля по направлению; server_time и revision назначает сервер. Нельзя молча изменить канон. Включать `request_id` для всех мутаций и `result`/error с корреляцией `request_id`. `trace_id` выдаёт сервер или безопасно нормализует клиентское значение. Публичные идентификаторы и revision — не секреты.

**Версионирование:** major `protocol_version` на envelope; `content_build_id` отдельно; additive поля допускаются, неизвестные события игнорировать/логировать по политике, несовместимый major отклонять явной ошибкой с кодом и инструкцией обновления. На reconnect согласовывать supported versions и content build. Схему и список кодов должен опубликовать director в `docs/contracts/**`.

## 6. Жизненный цикл и защита

1. **Connect/auth:** HTTPS login выдаёт краткоживущий одноразовый WS ticket (или согласованный auth token). WSS Upgrade, первое `session.auth` за ≤5s (предложение, не канон); сервер проверяет ticket, expiry, revocation, user/character binding и присваивает session_id. До auth запрещены игровые команды; лимит pre-auth соединений по IP. TLS и проверка Origin там, где применимо (Origin Android может отсутствовать; не считать Origin аутентификацией). Никогда не доверять client character_id, position, damage, quest state, currency.
2. **Heartbeat:** server WebSocket Ping каждые 20–30s (предложение), ожидание Pong ≤10–15s и отслеживание последней активности; Godot регулярно poll. При мобильном background допустим reconnect, не штрафовать за пропущенный heartbeat; ограничения idle и proxy проверить end-to-end. Дополнительный app heartbeat только если нужен RTT/server_time, не дублировать бесцельно.
3. **Reconnect/resume:** экспоненциальный backoff с jitter, например 0.5→1→2→4→8→15s, с верхним пределом. Новая авторизация; сервер возвращает актуальные revisions и подписки interest/channel. **Не** полагаться на сохранность очереди при разрыве. Resume только после проверки владельца и срока жизни resume token. При пропуске revision — snapshot; после него новые дельты применяются последовательно, не «на глаз».
4. **Idempotency:** `request_id` (UUID) + account/character + operation scope, дедупликация на сервере с durable ledger для `quest.accept`, `quest.turnin`, `reward_claim_id`, покупки. Повтор запроса возвращает прежний результат, не выдаёт награду повторно. При повторном request_id с другим payload — conflict. Истина в БД-транзакции/unique constraints, не в RAM websocket-сессии. [Канон §15.1/§16](../content/14_CONTENT_INTEGRATION.md).
5. **Rate limits:** token bucket по IP на handshake и по authenticated session/account на команды, отдельные лимиты для movement, combat, dialogue, quests и chat. Лимиты как **проектные гипотезы**: 10–20 movement intents/s, 2–5 quest mutations/s, burst до 2×, настраиваются после нагрузки; лимиты на размер входящего JSON (например 16 KiB обычные команды, отдельные более крупные ответы), число полей, nesting, subscriptions. Не доверять timestamp клиента, server проверяет скорость и cooldown. Ввести `RATE_LIMITED` + retry_after_ms, журнал подозрительных повторов.
6. **Backpressure:** один ограниченный outbound queue на сессию, один writer loop; не блокировать игровой tick записью в медленный сокет. При переполнении coalesce/drop только заменяемые позиционные дельты; **не терять** результаты квестов/ledger. Для критических событий: ограниченная очередь + resync/close slow consumer, затем восстановление по БД/snapshot. Метрики queue depth, dropped deltas, write latency, close reason. Отдельный максимум сообщения и timeout на запись. Отключить compression до измерений (CPU, memory, CRIME/BREACH-подобные риски при смешении секретов и контролируемого текста). [RFC7692](https://www.rfc-editor.org/rfc/rfc7692).
7. **Tick/interest:** стартовая **гипотеза** server simulation 10–20 Hz, snapshot/дельты 5–10 Hz для nearby actors; не обещать 30/60 Hz без профилирования. AOI по региону/каналу/дистанции, сервер валидирует входящие input intents и авторитетно рассчитывает позиции, урон, XP. Дельта содержит `base_revision`, `revision`, `server_tick`, изменённые/удалённые entity IDs; полные snapshot при входе, разрыве последовательности, смене региона, превышении бюджета очереди. Quest/inventory revisions раздельные от world revisions. Для точности расчёта движения и защиты от replay — monotonic input sequence и ограничение времени. [ARCHITECTURE](../ARCHITECTURE.md).
8. **Security/ops:** WSS, лимит handshake, HTTP headers, запрет произвольного Origin для browser-клиентов, no secrets in logs, не логировать payload токенов, structured trace, ограничения read/decompression, защитить от zip bombs, slowloris, malformed JSON, replay, multi-session abuse. Shutdown: http.Server.Shutdown не ждёт hijacked WS, нужен explicit session registry и close/drain. [Go net/http](https://pkg.go.dev/net/http#Server.Shutdown), [RFC6455 security](https://www.rfc-editor.org/rfc/rfc6455#section-10).

## 8. Рекомендация, Phase 2 и критерии

**Выбрать `github.com/coder/websocket@v1.8.15`** (ISC, Go 1.23, ноль внешних require на теге). **Резерв `github.com/gorilla/websocket@v1.5.3`** (BSD-2-Clause, Go 1.12). Для Godot: штатный WebSocketPeer + JSON без сжатия, WSS, ограниченные очереди, snapshot/resync. Не внедрять Centrifuge в первый vertical slice. Решение условное: сначала директор утверждает контракт и Go toolchain.

**Потребуется в Phase 2, после OK:** (а) Go **1.25.x или более новый одобренный**, с пином patch/digest в CI (точный patch **не проверен**); (б) один модуль `github.com/coder/websocket v1.8.15` **или** `github.com/gorilla/websocket v1.5.3`, но не оба; (в) встроенные `net/http`, `context`, `encoding/json`, `crypto`, `time`, `sync` — без установки; (г) существующий Godot WebSocketPeer, отдельный addon не требуется; (д) тестовые сертификаты и инструменты тестирования WS, если понадобятся (версии **не проверены**). Никаких `go get`/установок в Phase 1.

**Phase 2 gate:** unit tests на авторизацию, размер и malformed frames, deadline/ping/pong, request_id replay, ledger exactly-once effects, revision gaps, AOI, slow consumer, shutdown; `httptest.Server` проверяет upgrade **через statusWriter** и HTTP 101; Go `go vet ./...`, `go test -race ./...`, `govulncheck`; Godot 4.3 (до одобренного апгрейда) на Android проверяет poll/reconnect/WSS, мобильный фон, 2 аккаунта и 6 ГБ память. Нагрузочные значения: p95 send latency, queue depth, bytes/s, RAM/connection, goroutine count; критерии количественно согласовать с director.

**Открытые вопросы директору:** (1) направление обязательных полей envelope в §15.2, (2) имена auth/error/snapshot/movement событий, (3) lifecycle и retention idempotency keys, (4) Go patch pin, (5) rate limits/tick budgets, (6) отдельный контракт `docs/contracts/**` до EX-P04/P05. Всё это **не проверено/не утверждено** как канон. VPS, client/server/CI/канон не менялись.
